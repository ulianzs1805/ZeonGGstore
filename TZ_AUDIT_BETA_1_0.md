# ZeonGGStore Beta 1.0 — аудит текущего этапа ТЗ

Этот файл фиксирует прогресс по текущему этапу разработки, чтобы не ходить по кругу и не проверять функции, которые ещё не планировалось создавать.

Статусы:
- DONE — проверено и реализовано.
- PARTIAL — есть часть реализации, требуется отдельная проверка/доработка.
- VERIFY — требует ручной или серверной проверки перед Beta.
- LATER — будущая функция, пока не входит в текущий этап и не проверяется как ошибка.

## 0. UI/UX аудит по ТЗ

### Визуальный стиль
- DONE — текущая основа тёмная, с неоновыми акцентами, свечением и аккуратными карточками.
- PARTIAL — в текущем UI сильно доминирует фиолетовый, поэтому при следующих точечных правках нужно сохранять палитру ТЗ: фиолетовый, голубой, оранжевый, красный и бордовый, а не превращать интерфейс в один сплошной violet-тон.
- PARTIAL — общая главная страница уже выглядит современной и динамичной, но полный аудит остальных пользовательских страниц ещё требуется.

### Фоновая система
- PARTIAL — есть спокойный тёмный фон, градиенты и мягкие световые эффекты.
- VERIFY — атмосферные элементы вроде частиц/погоды должны оставаться фоновыми и не мешать интерфейсу; не добавлять их ради эффекта на каждой странице.

### Главная страница
- DONE — есть hero-блок, последние дропы, популярные кейсы и карточки преимуществ.
- PARTIAL — после полного UI-аудита проверить разделы баннеров, новинок, акций и новостей относительно текущего этапа ТЗ.

### Навигация
- PARTIAL — desktop header сейчас содержит Кейсы, Бонусы и Профиль.
- PARTIAL — мобильная нижняя навигация приведена к текущей структуре разделов, при этом центральный Z-Coin оставлен как основной быстрый элемент по решению владельца проекта.
- VERIFY — навигация и быстрый доступ к текущим разделам должны быть одинаково понятными на desktop и mobile.

### Мобильная версия
- PARTIAL — текущий код использует responsive Tailwind breakpoints.
- VERIFY — нужен визуальный регресс на реальных мобильных размерах: iPhone и Android, чтобы не было наложений, мелких кнопок и недоступных действий.

### Карточки предметов и кейсов
- DONE — используются отдельные аккуратные карточки и glow-акценты.
- VERIFY — UI не должен ломаться при длинных названиях, отсутствии PNG и загрузке изображений.

### Инвентарь и профиль
- PARTIAL — структура профиля и инвентаря уже реализована: отдельные разделы, история, статистика, настройки и поддержка.
- VERIFY — проверить визуально на desktop/mobile и привести акценты редкостей и карточек к единой палитре без лишней косметики.

### Бонусы и промокоды
- VERIFY — провести отдельный UI-аудит текущей страницы бонусов и формы промокодов.

## 1. Текущий этап разработки

### Кейсы и дроп
- PARTIAL — кейсы, открытие, отображение дропа и процентов уже дорабатывались.
- DONE — открытие кейса выполняется на сервере внутри database transaction.
- DONE — повтор одного idempotency key не создаёт вторую операцию открытия.
- DONE — при успешном открытии баланс, предмет в инвентаре, Operation и Transaction создаются в одном серверном сценарии.
- VERIFY — фактический регресс-тест через сайт и реальную базу после деплоя.
- PARTIAL — StatTrack требует отдельной проверки после появления корректных PNG-ассетов.

### Изображения предметов
- PARTIAL — загрузка PNG уже исправлялась.
- VERIFY — изображения не должны пропадать во время открытия и должны корректно появляться после результата.
- LATER — отдельные PNG для StatTrack будут добавляться только после появления готовых ассетов.

### Инвентарь и выпавшие предметы
- PARTIAL — выпавший предмет создаётся сервером вместе с операцией открытия.
- DONE — продажа предмета выполняется в database transaction: баланс начисляется, предмет помечается проданным и создаются журналы операции.
- VERIFY — реальный регресс: один предмет после открытия, одна продажа, без дублей и повторного начисления.

### Стоимость предметов
- PARTIAL — ручное управление ценами уже дорабатывалось.
- VERIFY — изменение цены не должно случайно менять вероятность или существующий инвентарь.

### Авторизация и профиль
- PARTIAL — Google OAuth исправлялся и вход работает по последней проверке.
- VERIFY — регресс после следующих деплоев.

### Промокоды
- PARTIAL — создание и активация проверялись.
- VERIFY — защита от повторной активации, лимиты и журналирование.

### Z-Coin и баланс
- PARTIAL — ручное управление балансом уже дорабатывалось.
- VERIFY — все изменения баланса проходят через сервер и не допускают повторного применения.

### Админка текущего этапа
- PARTIAL — кейсы, дроп, промокоды, Z-Coin, роли, Dev Console и цены уже дорабатывались.
- Важно — не делать новую косметику существующих панелей без отдельной причины по ТЗ или найденной ошибки.

## 3. Будущие функции — пока не проверять как ошибку

Следующие режимы пока отсутствуют намеренно и относятся к следующим этапам разработки:
- Апгрейдер — LATER;
- Контракты — LATER;
- Башня — LATER;
- другие игровые режимы, которые ещё не были начаты.

Их отсутствие не является текущим багом и не должно отвлекать от доработки существующего функционала.

## 4. Архитектурные правила текущего этапа

Все важные решения должны проходить:

Пользователь -> интерфейс -> Backend -> проверка -> игровая логика -> Database -> результат -> интерфейс.

Клиент не является источником истины для:
- Z-Coin;
- результатов открытия кейсов;
- инвентаря;
- вероятностей;
- критических административных операций.
